Resumo
======

Nesta sessao foi planejado, implementado e documentado um plugin local do
Omarchy Shell chamado `mat.reminder-countdown`.

O objetivo foi adicionar uma contagem regressiva na top bar para o proximo
`omarchy reminder`, com suporte a multiplos reminders e um sinalizador piscante
quando algum reminder vence. O sinalizador permanece visivel ate o usuario
clicar nele, enquanto o countdown do proximo reminder continua normalmente.

Contexto inicial
================

O pedido inicial foi:

- Existe o recurso `reminder` no Omarchy.
- O usuario queria mostrar na top bar o tempo restante ate o proximo reminder.
- Exemplo: criar um reminder para "tomar cafe" em 5 minutos e ver uma contagem
  regressiva na barra.
- Se houver mais de um reminder, a barra deve sempre mostrar o mais proximo.
- Quando o reminder mais proximo vencer, a contagem deve passar para o proximo.
- Alem da notificacao ja existente, deveria aparecer um sinalizador piscando
  indicando que um timer chegou.
- Esse sinalizador deveria sumir apenas quando o usuario clicasse nele.
- A solucao deveria ser portavel.

Descobertas importantes
=======================

1. O comando `omarchy reminder show --json` ja existe.

   Ele retorna uma estrutura com:

   - `count`
   - `active`
   - `tooltip`
   - `reminders[]`

   Cada reminder inclui informacoes como:

   - `unit`
   - `timer`
   - `label`
   - `message`
   - `remaining`
   - `remainingSeconds`
   - `at`
   - `atTime`

2. O indicador nativo do Omarchy para reminders existe em:

   `/usr/share/omarchy/shell/plugins/bar/indicators/Reminder.qml`

   Ele mostra apenas um icone/estado, consulta `omarchy-reminder show --json` e
   abre a lista de reminders ao clicar.

3. A barra aceita widgets customizados de usuario como plugins em:

   `~/.config/omarchy/plugins/<plugin-id>/`

4. A configuracao da barra fica em:

   `~/.config/omarchy/shell.json`

5. A abordagem portavel mais segura seria criar um plugin local em
   `~/.config/omarchy/plugins/`, sem editar arquivos em `/usr/share/omarchy/`.

Planejamento
============

Foi discutida a melhor abordagem para implementar o comportamento.

Opcoes consideradas:

1. Plugin local de usuario.

   Vantagens:

   - Portavel.
   - Seguro contra updates do Omarchy.
   - Nao altera `/usr/share/omarchy`.
   - Usa APIs publicas existentes.

2. Modificar o Omarchy upstream.

   Vantagens:

   - Integracao mais profunda.

   Desvantagens:

   - Menos portavel para uso local.
   - Poderia exigir manutencao do pacote ou PR upstream.

3. Modulo simples `type: command`.

   Vantagens:

   - Mais simples.

   Desvantagens:

   - Limitado para estado piscante, clique e logica rica.

Foi escolhida a abordagem "plugin local".

Plano aprovado
==============

O plano foi criar um plugin `mat.reminder-countdown` com:

- `manifest.json`
- `BarWidget.qml`

Comportamento planejado:

- Consultar `omarchy-reminder show --json` periodicamente.
- Escolher o reminder com menor `remainingSeconds`.
- Mostrar o countdown na top bar.
- Quando um reminder vencer, mostrar `!` piscando.
- Se houver outro reminder ativo, continuar mostrando o countdown do proximo.
- Clicar no widget limpa apenas o sinalizador visual.
- Se nao houver sinalizador, clicar mostra reminders ativos ou abre o fluxo de
  criacao.

Limite encontrado
=================

Quando o usuario testou com multiplos timers, encontrou um cenario especifico:

- Reminder 1: "escovar os dentes" em 1 minuto.
- Reminder 2: "tomar banho" em 3 minutos.

Comportamento correto ja existente:

- Quando o primeiro vence, o timer do proximo inicia corretamente.

Comportamento desejado adicional:

- Mesmo iniciando o proximo timer, o sinalizador piscante deve continuar ate o
  usuario clicar.

A primeira implementacao usava apenas `lastSeenUnit`, ou seja, lembrava de um
unico reminder visto anteriormente. Isso era fragil para multiplos timers,
porque a logica podia ser sobrescrita pelo proximo reminder ativo.

Correcao multi-timer
====================

Foi criado um plano para separar o estado do countdown atual do estado de alerta
pendente.

Mudanca implementada:

- Remover a dependencia de um unico `lastSeenUnit`.
- Adicionar `seenReminders`, um snapshot dos reminders vistos no ciclo anterior.
- Adicionar `expiredLabel` para guardar o texto do reminder vencido.
- Comparar `seenReminders` com a lista atual retornada pelo JSON.
- Se um reminder anteriormente visto desaparecer depois do seu `at`, marcar:

```qml
expiredPending = true
expiredLabel = previous.label
```

Com isso:

- `nextReminder` continua apontando para o proximo reminder ativo.
- `expiredPending` continua verdadeiro ate o clique.
- A UI pode mostrar `󰢌 ! 1:59`.

Funcoes adicionadas ou alteradas:

- `snapshotReminders(items)`
- `markExpiredFromMissing(items)`
- `updateFromData(data)`

Resultado esperado:

- Antes do primeiro vencer: `󰢌 0:59`
- Depois que o primeiro vence, com o segundo ativo: `󰢌 ! 1:59`
- Ao clicar: o `!` desaparece, mas o countdown continua.

Comportamento final do plugin
=============================

O plugin:

1. Consulta `omarchy-reminder show --json` a cada segundo.
2. Seleciona o reminder ativo com menor `remainingSeconds`.
3. Mostra o countdown na barra.
4. Guarda snapshot dos reminders vistos anteriormente.
5. Detecta reminders vencidos quando eles desaparecem da lista apos o horario
   esperado.
6. Mostra `!` piscando quando ha reminder vencido pendente de reconhecimento.
7. Continua mostrando o timer seguinte mesmo enquanto o `!` pisca.
8. Remove o sinalizador visual quando o usuario clica.
9. Nao cancela nem edita reminders.
10. Nao modifica arquivos do pacote Omarchy em `/usr/share/omarchy`.

{

- `hideWhenEmpty: true`: esconde o widget quando nao ha reminder ativo nem
